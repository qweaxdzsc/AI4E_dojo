# 方针提炼与复核流程（/distill）

## 何时运行

**仅当显式调用**（`@distill` 或让你"跑一次提炼"）。
绝不在普通编码任务里主动触发——提炼是独立的、定期的动作，不是每次犯错就做。

## 输入 / 输出文件

- `error.log`（根目录）：原始错误日志（矿石），由 `error-log.mdc` 规则日常追加。
- `error_distill.log`（根目录）：三层筛选池，本流程维护的中间产物。
- `.cursor/rules/lessons.mdc`：作战方针成品集（每轮加载的应用规则），只收第三层毕业方针。
- 当前 PRD / 架构事实（必要时向我确认）。

## 三层筛选池（核心机制）

`error_distill.log` 不是按"领域"分层，而是按方针的**耐用度阶梯**晋升：

| 层级 | 含义 | 去向 |
|------|------|------|
| 第一层 · 具体问题解决方针 | 绑定某个 bug/模块，只能挡住那一次 | 留池子 |
| 第二层 · 架构方针 | 跨某个子系统成立的组织范式 | 留池子 |
| 第三层 · 作战方针 / 设计哲学 | 跨模块跨功能的根本工作方针，一两句话 | **毕业进 lessons.mdc** |

- 新候选默认落第一层。
- 复盘时若被反复验证、且更普适，逐级上升（L1→L2→L3）；**只有升到第三层才毕业进 `lessons.mdc`**。
- L1/L2/L3 全部条目长期留在池子里作为工作集，不丢弃；每次晋升都在条目"履历"里追加一行。

## A. 提炼新方针（写入池子）

1. **聚类**：读 `error.log`，按"类别"标签聚类。**只处理"状态=未提炼"且复发 ≥ 2 次的类别**。单次出现一律跳过——单次是噪声，不配上升为方针。

2. **内部推导（脚手架，不要写进任何成品文件）**：对每个复发类别，先用五栏想清楚——
   - 现象：反复出现的错误行为
   - 机制/根因：为什么会这样（透过现象看本质，不要停在"那次那个函数错了"）
   - 适用条件：什么情况下成立，以及什么情况下*不*成立
   - 方针：该怎么做
   - 边界/反例：什么时候照做反而错
   这五栏只是推导和判断用的脚手架，想清楚之后就拆掉。

3. **压缩入池**：把它压成一两句话的方针，**条件焊进措辞**，作为候选写入 `error_distill.log` 第一层。先不急着往上抽——晋升交给复盘验证。

4. **定层与晋升判定**：用"毛选三测"判断它当前够格停在哪一层：
   - **跨类挡杀**：它能同时解释并预防池子里 ≥2 个不同复发类别的错误？只挡一个类别 = 停 L1/L2。
   - **讲作战方式，不讲具体写法**：不绑定某个 API / 表 / 函数？换个模块照样成立？
   - **一两句话说清，且能直接导出行动决策**？
   三测全过 → 够格升 L3（作战方针），可毕业进 lessons；只过部分 → 停在 L1（绑具体）或 L2（跨子系统但未跨类）。

5. **比对现有方针**：判断它是【新增到某层】/【合并进池子某条】/【与 lessons 某条冲突】/【取代某条旧方针】。

## B. 复核现有方针（把 error.log 反过来用）

6. 对 `error_distill.log` 池子里每一条候选，查它针对的错误类别在记录之后是否还在 `error.log` 复发：
   - 不再复发且通过更高层的毛选三测 → 提议【晋升一层】
   - 仍属本层、未达上层条件 → 【留原层】
   - 仍在复发 → 失败，提议【改】（多半是瞄错层或措辞不对）
   - 误开火 / 与它冲突的新错 → 提议【收窄或杀】

7. 对 `lessons.mdc` 里每条 L3 作战方针：
   - 对应错误不再复发 → 【保留】
   - 仍在复发 → 提议【改】（多半瞄错层）
   - 出现可追溯到它误开火的新错 → 提议【收窄或降回池子或杀】
   - 在当前 PRD 下已不成立、或长期无任何使用痕迹 → 提议【杀】

8. **放手杀**：误杀无妨——真正承重的方针，对应错误会再复发、自动重新触发提炼，从前门走回来。不要因为"留着以防万一"而囤积。

## 输出（关键：不要自己动手改文件）

用一张清单列出所有建议，每条注明：
- 动作：【新增入池 / 晋升一层 / 合并 / 改 / 杀 / 保留 / 毕业进 lessons】
- 方针正文（如涉及新增或修改）+ 目标层级
- 一句理由 + 通过了毛选三测的哪几条
- 来源：对应的 error.log 日期/类别

**不要自己修改 `error_distill.log` 或 `lessons.mdc`。** 等我逐条拍板。

## 我确认后

- 更新 `error_distill.log`：写入/晋升候选，在条目"履历"里追加一行带日期的晋升/复盘理由。
- 升到 L3 的方针毕业写入 `.cursor/rules/lessons.mdc`，补上 `来源:` 标注与当日 `复盘:` 记录行。
- 把 `error.log` 里已处理条目的"状态"改为 `已提炼→[层级·编号]`，避免下次重复计数。
- 复盘记录只在这一步写（一句话，带日期），它是方针的履历——某条若反复被改或被降级，说明它本身没提对、层级不对。

## 维护纪律（重要）

- `lessons.mdc` **只由本流程在你确认后修改**。日常编码中不要随手往里加东西——随手加就变回流水账。
- 每条 L3 方针都必须能通过两个测试，否则不该存在：
  - **行为改变**：找得到一个具体决策点，遵守它和不遵守它会导出*不同*的行动。
  - **当前事实**：在当前 PRD / 架构下仍然成立。
- **条件焊进措辞里**，不另起前提段。一条方针若离不开一大段前提才不误开火，说明它该往上抽一层、或拆成两条。
- `lessons.mdc` 要短，宁缺毋滥。新增一条前先想：能不能合并进已有的某条？

## 条目格式

`error_distill.log` 池子候选：

```
### [候选ID] 一句话方针（条件焊在措辞里）
- 当前层级: 第一层 / 第二层 / 第三层
- 来源: <error.log 日期 / 类别>
- 履历: <YYYY-MM-DD: 入池 L1 / L1→L2 理由 / 复盘结论>
```

`lessons.mdc` 毕业方针：

```
### [编号] 一句话作战方针（条件焊在措辞里）
- 来源: <error.log 日期 / 类别>
- 复盘: <YYYY-MM-DD: 结论>
```
