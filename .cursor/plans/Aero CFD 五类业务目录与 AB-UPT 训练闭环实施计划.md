# Aero CFD 五类业务目录与 AB-UPT 训练闭环实施计划

## 业务描述总结

- **做什么**
  - 按已经确定的五类业务职责组织外流应用：
    - `rawprep`（原始数据处理）：形成可跨项目复用的数据集。
    - `trainprep`（训练数据准备）：形成面向项目和模型输入要求的数据。
    - `model`（模型设置）：定义模型和学习目标。
    - `train`（训练设置与执行）：组织一次训练任务。
    - `post`（后处理）：推理、评估、分析与结果导出。
  - 完整包含原计划 1 的归一化与采样、原计划 2 的批次与训练闭环，并补齐监督目标、真实模型接入、归一化记录和续训验收。
  - 将完整 AB-UPT 纳入贡献模型组件；核心层保留通用算法与模型组成部分。
  - 原始数据、准备数据、模型配置与运行结果分别管理，支持跨项目和同项目多次实验复用。

- **怎么做**
  - 原始数据处理与训练数据准备分开，避免模型输入要求污染公共数据集。
  - 应用目录按业务目的划分，目录内聚合稳定流程；经常变化的方法、参数和策略在 recipe 中公开。
  - 模型设置选择网络和学习目标；训练设置选择优化器、批次、运行方式与保存策略。
  - 归一化方法同时记录于配置、数据旁和检查点，训练与反归一化共用实际参数。
  - 数据保存能力写数据产物，运行写入方写日志、报告和检查点。

## 讨论

### 1. 本次确定的目录原则

```text
applications/aero_cfd/
├── rawprep/       原始数据处理
├── trainprep/     训练数据准备
├── model/         模型与学习目标设置
├── train/         训练设置与执行
└── post/          后处理
```

划分依据：

- 一级目录按业务目的、交付结果和变化原因划分。
- 同一业务内功能相似、顺序稳定的操作形成默认流程。
- 一个文件承载一个完整功能，不按单个函数、正反操作或状态对象拆文件。
- 业务阶段与实际执行顺序分开：可以先确定模型输入要求，再执行训练数据准备；续训可以直接消费已有准备数据。
- CAE 数据产生不进入本框架；报告暂不作为独立实施模块。

### 2. 原始数据与训练数据的复用边界

**原始数据处理负责公共工程数据。**

读取、校验、清洗、通用字段提取、几何派生和存储均不依赖具体网络规模。VTKHDF 保留可追溯的网格和场，PT 提供张量读取形式，两者通过样本与实体身份关联。

**训练数据准备依赖输入与任务要求。**

字段选择、分片、归一化、编码、几何采样、目标组织属于项目准备过程。不同模型只要输入要求相同，就可以复用。

- 改模型宽度、深度、优化器，不使准备数据失效。
- 改字段、变换或固定输入布局，形成新的准备版本。
- 每轮随机采样按需执行，不把随机锚点结果混入公共数据集。
- 原始数据的描述性统计不自动等同于项目训练统计；拟合归一化统计必须明确训练样本范围。

### 3. 模型、学习目标与训练执行的边界

- 网络结构、初始化权重、冻结策略、预测目标、损失函数及物理约束配置归 `model`。
- 优化器、学习率、批次大小、设备、精度、训练轮数、监控和检查点策略归 `train`。
- 损失算法仍由原子约束能力实现，不写进 AB-UPT 网络。
- 批次大小与迭代策略由训练设置决定；字段拼接和索引偏移由准备阶段选择的收批组件提供。
- 周期验证由训练触发，评估算法复用能力层；训练不反向调用整个后处理流程。

### 4. 模型来源与核心提炼

- 完整 AB-UPT 放在贡献包模型目录，应用层只使用它。
- recipe 引用贡献组件并传入应用，core 不静态导入 contrib。
- 本期提炼前馈网络、连续正余弦编码和旋转位置频率到核心模型能力。
- 特有的锚点注意力、分支交互及完整网络组装保留在 AB-UPT 中。
- 不实现其他正式模型，不创建 Transolver 等占位目录。

文档按本轮要求集中：

- contrib 每个模型保留 README 和 LICENSE，简要修改记录写入 README。
- core 组件不新增单独 README、LICENSE、Notice，保留必要源码署名与来源说明。
- 许可原文和归属集中维护，不因提炼组件改变适用许可。AB-UPT 原许可要求的分发署名在分发产物中保留，不在各功能目录重复铺设说明文件。

### 5. 本期范围与默认行为

- 本期完成五类职责划分，以及原功能表第 40–64 项和必需的初始化。
- `rawprep` 迁移现有前处理，并补公共 VTKHDF 与张量身份关联交付。
- `post` 本期交付评估应用；完整网格推理、云图和三维预测导出作为该目录后续职责，不借目录存在宣称实现。
- 归一化默认内存执行，支持显式物化。
- 默认训练两轮、批次一、单设备、单优化器、零读取子进程。
- 默认 AdamW、学习率 `5e-5`、权重衰减 `0.05`、梯度裁剪 `1.0`、滑动平均因子 `0.9999`。
- 默认 test 总损失选择 best，同时支持显式 eval 分片。
- 本期不实现 Lion、预热、余弦调度、分布式和梯度累积；记录与 Noether 的差异。
- 仅保证轮次边界恢复，真实模型门禁与框架机制测试分别记录。

### 6. 已确认分叉（对照现行仓库后的实施意见）

下列两项已确认，实施时必须先改入口与架构文档，再动目录和模型源码：

- 本轮就把应用层改成五类目录，并迁移全部调用方。
- 完整 AB-UPT 进入 `contrib/ability/model/abupt`，同步改 `AGENTS.md`、MVP1 与架构中「独立模型仓 + 只做 adapter」的旧句。

现行仓库不是一张白纸。计划正文原先按「从零建训练」写，必须按下面现状接线，否则第一步就会和已交付行为打架。

**已经落地、计划不得另起一套**

- 案例在根目录 `recipes/aero_cfd/`，不是安装包；只有 `pre.py` / `pipeline.py` / `config.yaml`，**没有** `train.py`，配置里**没有** `train:` 段，默认只开 `pre`。
- 开车已是 `run/session.py` 的 `launch`：一次配置、一次运行记录。`normalization.execute=true` 已会报尚未实现。不要再新增平行的 `run/training.py` 第二入口。
- Dataset 按需执行、产物 `manifest.json`、训练清单读盘、contrib 的 ShapeNet 数据集适配已经交付。`train/read.py` 已能按清单或对照表读物理样本并派生表面零距离。
- 现有 `train/standard.py` 仍是「选定 AB-UPT + 九个占位 + 读探测样本」。读盘探测用例断言这九个占位。取消占位时必须改该用例，不能让旧断言挡住闭环。
- `run/writer` 仍只写配置、日志、摘要，不写检查点。检查点只能扩这个写入方。
- `abilities/transform`、`sampling`、`constraint`、`training`、`modeling`、`eval` 仍是空目录。第 40–46 项的归一化/采样计划尚未实施。

**计划原文里缺、本轮必须补上的**

- **先改约定再改代码。** 五类目录与架构里的 `pre/model/train/post` 不一致；完整模型进 contrib 与现行 AGENTS/MVP1 不一致。第一步是 ADR + 改 `AGENTS.md`、架构 §5.2、MVP1、算法规则里 recipes 只含 `pre/pipeline` 的句子（本轮要新增 `train.py`）。
- **机械改名与新能力分开验收。** `pre` → `rawprep` 必须先做到行为不变：导入、动态导入、`tests/legacy_pre.py`、案例阶段名仍叫 `pre`。不得把 VTKHDF 写出、归一化、训练循环塞进同一次「改名提交」。
- **VTKHDF 写出不挡 40–64。** 读 VTKHDF 已支持；写出与实体映射是后处理回贴需要的扩展。可在 rawprep 迁完后做，但 trainprep 必须能继续消费现有 `.pt` + 清单。未写出 VTKHDF 时，训练闭环仍要能跑。
- **不要用完整 FieldSpec 卡住训练。** spec 仍几乎为空。本轮用与现有清单/场字典同级的最小交接即可；`ai4e-spec` 的 Sample/Batch 专章可并行起草，不作为 40–64 门禁。
- **归一化声明要接到现有配置。** 案例已有 `normalization.execute` 与 `paths.datasets.normalize`。trainprep 的方法记录必须消费这套键，而不是再发明第二套互不认识的声明。
- **探测样本三份分开。** 读盘字典保持物理形状（已有读盘用例依赖）；归一化全分辨率、采样后的模型输入各用自己的上下文键。第 47 项在 trainprep 复制目标，不覆盖原压力/速度键。
- **搬进 contrib 的是可安装源码，不是本机路径。** 独立参考仓库目前用相对导入、一批大于 1 会失败、解码键是扁平锚点名。迁入时要改成包导入、锁定版本与 LICENSE，并在启动时显式拒绝批次大于 1。提炼到 core 的前馈与位置编码必须有数值等价测试，避免两份正式副本。
- **真实模型门禁在迁入后才能算完成。** 替身骨干只证明接线；H4 必须对 contrib 内的正式网络跑通单步与短训。迁入未完成时整体计划保持未完成。

**建议实施顺序（仍属同一份计划，验收按段切开）**

1. 改 ADR / AGENTS / 架构 / MVP1 / 案例「只含 pre」的句子。
2. `pre` 整体迁到 `rawprep`，案例阶段名仍为 `pre`，只跑现有前处理与读盘回归。
3. 把 `train/read` 的读盘/清单职责迁到 `trainprep`，九个占位先原样跟上，不在这一步取消。
4. 落地变换、采样、目标复制（40–47），接到现有 `normalization` 声明；探测三字典分开。
5. 迁入 contrib 完整模型、提炼通用模块、应用层 `model` 接线与两条监督约束。
6. 落地收批、循环、评估、检查点（48–64）；扩展写入方；取消第 33–34 项占位。
7. VTKHDF 写出与身份映射：rawprep 迁完后即可插入，但不作为第 6 步的前置。
8. 案例补 `train.py` 与 `train` 配置段，登记到现有 `session.launch`；默认仍只开 `pre`。
9. 真实模型短训与轮次恢复；跳过则整体未完成。

## 实施评审

### 功能点

#### 主功能 A：形成可跨项目复用的工程数据集

归属 `rawprep`。

BDD：

- Given 原始网格和物理场可以读取。
- When 执行原始数据处理。
- Then 获得来源明确、字段可靠、网格与张量可关联的公共数据集。

子功能：

- **A1：迁移既有读取、校验、清洗和派生流程。**
- **A2：保存 VTKHDF、PT 和实体映射。**
- **A3：发布完整数据清单并保留失败恢复。**

约定：

- 现有 `pre` 整体迁入 `rawprep`，原子算法保持原位置。
- 通用几何派生仍由显式配置启用，不执行模型专用锚点或超节点采样。
- VTKHDF 保存可追溯的完整网格及具名场；PT 可以按有效性规则筛选，但必须保存到网格实体的映射。
- 明确 point/cell 归属和实体 ID，不通过数组顺序猜测对应关系。
- 当前支持的表面及体积网格必须分别进行 VTKHDF 写出与重读验证；不支持的类型或写入能力明确报错。
- 保留已有临时目录、备份、提升和失败恢复机制。
- 部分失败不发布完整数据清单；原始数据不被覆盖。
- 模型无关统计可以保存，但标清来源与范围。

#### 主功能 B：准备面向项目和模型要求的数据

归属 `trainprep`，覆盖第 36–39 项复用。

BDD：

- Given 已提交公共数据集和明确输入要求。
- When 打开项目训练数据。
- Then 获得按分片、字段及身份组织的按需数据视图。

子功能：

- **B1：选择样本、字段和项目分片。**
- **B2：识别物理或归一化数据状态。**
- **B3：提供按需读取与样本探测。**

约定：

- 清单解析一次建立索引，不逐样本重新解析。
- 清单不完整、字段状态混杂、形状或类型错误时失败。
- 物理样本统一标量通道并派生表面零距离。
- 已归一化数据不得再次补物理零距离或重复归一化。
- 训练不依赖原始网格目录仍然存在。
- 保留旧物理读盘能力，迁移其调用位置，不维持第二套新数据准备流程。
- 新准备视图可跨多次训练复用；模型参数变化不修改准备数据。

#### 主功能 C：归一化并记录可恢复的方法

归属 `trainprep`，覆盖第 40–41 项和反变换。

BDD：

- Given 数据状态及归一化声明明确。
- When 执行归一化准备。
- Then 得到内存视图或物化数据，并有足够的信息恢复物理量。

子功能：

- **C1：执行场量与坐标归一化。**
- **C2：保存冻结变换记录。**
- **C3：可选物化归一化数据集。**
- **C4：根据记录识别和反归一化。**

约定：

- 压力、速度、体积距离使用均值标准差；表面距离复用体积距离统计；法向不变。
- 两域坐标共用边界，默认映射到 `[0,1000]`，不居中。
- 统计源必须明确，非有限值、非正标准差、零跨度和通道不兼容均失败。
- 默认使用项目训练分片拟合统计；显式采用参考统计时记录该选择。
- 每种变换将正向、反向、校验和状态恢复放在同一功能文件。
- YAML 声明方法；数据旁记录方法版本、实际参数、字段绑定、来源清单摘要与统计范围。
- 内存模式保存版本化方法记录，不发布虚假的归一化数据清单。
- 物化模式保存全分辨率归一化数据，不保存每轮随机采样结果。
- 原物理清单保持物理状态；新数据使用独立清单，引用固定方法记录。
- train/eval/test 共用训练时冻结的变换，不各自拟合。
- 读取配置与数据记录冲突时失败；不根据目录名猜变换。
- 检查点内嵌同一记录，恢复不依赖原统计文件。
- 检查模式不写变换记录或数据文件。

#### 主功能 D：构造模型输入和监督目标

归属 `trainprep`，覆盖第 42–50 项中的样本准备与布局。

BDD：

- Given 模型输入要求与采样配置齐全。
- When 执行单样本准备和收批。
- Then 输入、目标及索引严格对齐，并满足选定模型的布局要求。

子功能：

- **D1：按公开算法与预算采样。**
- **D2：生成几何、锚点和监督目标。**
- **D3：提供收批组件和索引映射。**
- **D4：保持训练与验证随机策略可复现。**

约定：

- 均匀无放回采样位于 abilities，方法与参数在 YAML 可见。
- 默认几何最多 3586 点，不超过预算时保序；超节点 512，两域锚点各 256。
- 超节点或锚点候选不足时失败，不自动重复或减少预算。
- 几何只来自表面坐标，不含标签。
- 同域坐标、标签与身份共用下标。
- 保留标准压力、速度，独立复制两个监督目标；默认查询数量零。
- 几何批次索引在收批时生成，超节点按各样本实际几何点数偏移。
- 收批布局由模型组件提供，训练设置决定批次大小和调用时机。
- 模型前向只收到声明输入，目标不进入前向。
- 训练种子包含轮次；验证固定；各操作随机流独立。
- 同样输入要求的多个训练任务可以共享稳定准备结果。
- 改采样预算不重做无关的公共数据处理或归一化物化。

#### 主功能 E：设置 AB-UPT 与学习目标

归属 `model`，覆盖模型构造、第 51–57 项。

BDD：

- Given 模型组件、网络参数和学习目标已声明。
- When 设置外流模型。
- Then 获得可训练模型和独立监督约束，二者可以分别配置。

子功能：

- **E1：引入完整模型并提炼核心组件。**
- **E2：检查模型要求并完成领域接线。**
- **E3：设置初始权重和冻结策略。**
- **E4：设置监督损失和权重。**

约定：

- 完整模型位于 `contrib/ability/model/abupt`，无需依赖本机外部源码路径运行。
- 锁定上游版本及引入清单，README 简要记录本地修改。
- 前馈和位置编码提炼后，由完整模型引用核心实现；不维护两份正式副本。
- 模型入口为应用层 `model/abupt.py`，通过 recipe 注入贡献构造器。
- 默认宽度 192、几何深度 6、三头、`p + sc × 5` 交互块、每域十二层、半径九。
- 保留当前独立实现的表面四通道、体积七通道布局，选择压力和速度恢复为命名预测。
- 当前真实模型拒绝批次大于一，限制在启动检查中显式暴露。
- 模型层设置网络参数、初始化、冻结策略；优化器与学习率归训练设置。
- 两条监督约束在归一化空间计算 MSE，权重均为一。
- 预测目标形状必须一致，不允许广播；缺正权重字段或无有效损失时失败。
- 约束算法在 abilities，学习目标装配不写入网络源码。
- 本期不增加其他正式模型或物理约束实现。

#### 主功能 F：组织并执行训练任务

归属 `train`，覆盖第 33–34、58–61、64 项及恢复。

BDD：

- Given 准备数据、模型与监督约束已经就绪。
- When 执行训练任务。
- Then 参数更新、过程可监控、检查点可恢复，异常明确反映在运行结果中。

子功能：

- **F1：设置批次、优化器、设备和更新过程。**
- **F2：维护计数、监控和滑动平均。**
- **F3：触发验证并选择检查点。**
- **F4：保存状态并从轮次边界恢复。**

约定：

- 一次训练的稳定执行过程在应用层默认封装，不要求 recipe 声明清梯度等细节。
- 默认循环独占反向、裁剪和参数更新；自定义步骤返回可求导损失，不重复管理更新。
- CPU/CUDA/MPS 显式选择，不可用则失败；默认完整精度，可选 CUDA 混合精度。
- 需要梯度缩放时先解除缩放再裁剪；跳步不推进有效更新和滑动平均。
- 日志记录进度、分项损失、总损失、学习率和耗时，不倾倒张量。
- 默认每轮验证，best 按指定总损失严格改善更新，latest 每轮保存，正常结束写 last。
- 保存模型构造与源码标识、权重、字段要求、冻结变换、数据摘要、采样配置及完整续训状态。
- 续训状态含优化器、轮次、有效更新数、best、随机状态及已启用的缩放和滑动平均。
- 运行写入方原子提交检查点，失败保留旧文件。
- 初始权重加载属于 model；完整训练状态恢复属于 train。
- 恢复默认严格检查语义兼容，只允许调整总目标轮数、设备和日志频率。
- 训练输出包括检查点和运行记录；预测网格、误差场等归后处理。

#### 主功能 G：评估模型并形成分析结果

归属 `post`；本期覆盖第 62–63 项的评估复用。

BDD：

- Given 模型、评估数据和冻结变换。
- When 执行评估。
- Then 获得计算范围和统计口径明确的损失及物理空间指标。

子功能：

- **G1：计算归一化损失和六项物理指标。**
- **G2：累计有效数量并恢复模型状态。**
- **G3：支持训练中触发与独立评估复用。**

约定：

- 一次前向同时提供归一化损失与物理指标。
- 压力、速度分别计算 MSE、MAE、relative L2，默认逐样本计算再平均。

### 接口

**公共数据交接。** rawprep 输出物理数据清单，记录 VTKHDF、PT、字段和实体映射。trainprep 按清单消费，不了解原始文件命名。

**准备数据交接。** trainprep 返回项目分片、冻结变换、按需样本准备和收批组件。稳定数据允许物化，随机操作由训练迭代调用。

**模型与目标交接。** model 接收贡献构造器及领域配置，返回模型、输入输出要求和监督约束。模型要求可以先于数据准备确定。

**训练交接。** train 接收准备数据、模型、约束、训练配置和运行接口，执行默认训练流程并返回报告。不会解释原始网格路径。

**评估交接。** 评估任务包含分片、指标、变换和采样策略。训练周期调用与 post 独立调用共用能力实现。

**保存交接。** 数据及变换记录由数据保存能力提交；检查点、日志和运行摘要由运行写入方提交。应用只组织业务，不直接创建第二个写入方。

### 配置约定

保留当前原始数据和路径配置，新增或完善四组配置：

- `normalization`（归一化）：方法、统计来源、实际执行及是否物化。
- `sampling`（模型输入采样）：算法、几何／超节点／锚点预算、候选不足策略和随机种子。
- `model`（模型与学习目标）：组件、网络参数、初始权重、冻结策略及监督项。
- `train`（训练任务）：模式、批次、优化器、设备、精度、轮数、验证和检查点策略。
