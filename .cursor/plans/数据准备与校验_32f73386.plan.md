# 数据源：VTK 家族与 NPY 原生内存读取

### 业务描述总结

- **做什么**
  - 给处理工程数据的研究员提供按路径读取能力：VTK 家族文件读成原生 VTK 对象，NPY 读成原生 NumPy 数组。
  - 做成后保留原始拓扑、字段名称、字段位置、dtype、shape 和数值，不在读取阶段生成 PT 训练资产。
- **怎么做**
  - 通用读取检查路径和格式，再调用对应格式适配器。
  - VTK 适配器根据扩展名选择官方 reader；NPY 适配器使用 NumPy 原生加载。
  - 字段抽取、转换、训练张量生成和业务校验由后续 ingest/pre 完成。

### 讨论

- **路径与 locator**
  - 本阶段不引入 locator。单文件传路径，多文件与目录仍复用现有入口。
  - 数据集样本发现和跨目录配对等真实 recipe 出现需求后再设计。
- **YAML 边界**
  - source reader 不读取 YAML；删除当前配置式外流读取装配。
  - 通用配置模块和 recipe 配置草案继续保留，供未来完整 Pipeline 使用。
- **依赖边界**
  - 读取代码不导入 Torch；按用户确认，core 的 Torch 依赖暂时保留。

### 实施评审

#### 功能点

**主功能 A：完整读取 VTK 家族文件并保留原始数据**

BDD：

- Given 研究员提供一个已存在且属于支持范围的 VTK 家族文件
- When 研究员按路径读取该文件
- Then 得到对应的原生 VTK 对象，原始拓扑和全部字段保持不变

子功能：

- A1：读取 Legacy `.vtk`
- A2：读取 PolyData `.vtp`
- A3：读取 UnstructuredGrid `.vtu`
- A4：读取标准 `.vtkhdf` 并兼容 `.vtkh5`
- A5：损坏文件或内容与格式不匹配时明确失败

**主功能 B：按路径读取原生数据，不生成训练张量**

BDD：

- Given 研究员提供一个受支持的 VTK 或 NPY 文件路径
- When 研究员调用通用读取入口
- Then VTK 返回原生 VTK 对象，NPY 返回原生 NumPy 数组，不做字段抽取或 Torch 转换

子功能：

- B1：NPY 保留原始 dtype、shape 和数值
- B2：多文件读取保持输入顺序
- B3：目录读取识别全部已支持扩展名
- B4：文件不存在或扩展名未知时在进入适配器前失败

**辅助 C：移除原始读取对案例 YAML 的依赖**

- C1：删除 Aero CFD 当前的配置式读取入口
- C2：保留 recipe 配置和通用配置能力，但不接入 source reader

**辅助 D：同步治理资料并记录已核实返工**

- D1：同步 AGENTS、`.context`、模块 PRD、README 和当前计划
- D2：在 `error.log` 追加已核实的计划规范错误，不修改历史条目

#### 接口

通用读取在 `abilities/data/source/read.py`（路径读取）：文件路径和可选格式名进去，返回原生内存数据；多文件与目录入口分别返回对象列表及路径—对象列表。

格式适配在 `abilities/data/source/adapter/`（格式读取）：适配器只接收路径，返回 `vtkDataObject | numpy.ndarray`，不接收配置或数据集名称。

#### 架构改动

- source adapter 从“抽取可存 PT 的张量”改为“返回格式原生内存对象”，让读取与数据接入、训练物化解耦。
- 删除尚未进入完整 Pipeline 的配置式 pre 装配，避免 YAML 和 recipe 语义提前进入原始读取层。
- 不引入 locator、字段契约或数据集抽象；权威架构的总体目录与配置设计不变。

#### 实施步骤

1. 改造 VTK 适配器 → 五种扩展名均返回原生 VTK 对象。
2. 改造 NPY 与公共类型 → 返回 ndarray，读取链不再使用 Torch。
3. 更新通用路径读取 → 新格式可发现，既有失败边界保持。
4. 删除配置式外流读取 → source reader 只接收路径。
5. 重写相关测试 → A1—A5、B1—B4、C1—C2 均有验证。
6. 同步治理文档 → 现状、职责和后续边界与代码一致。
7. 只运行相关测试和代码门禁 → 全部通过后完成本计划。

- C2：核对 source reader → 不依赖 YAML、recipe 或配置模块；同一文件。
