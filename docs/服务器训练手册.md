# aero_cfd 五案例服务器训练与报告操作手册

日期：2026-09-10。执行目标：五个独立 example 各训练 **50 epoch**，顺序复用一张 CUDA GPU，固定五个测试样本全点评价，前三个出图，交付 NASA 与 ShapeNet 两份报告。

本文是当前入口的操作记录，不替代模块 PRD。已完成的历史实验是 MPS/fp32 **1 epoch**；本文的服务器 CUDA/50 epoch 尚未执行。不要把历史指标、耗时或通过状态填入新报告。

## 1. 实验范围与执行顺序

同一个 `recipes/aero_cfd` 支持以下五份配置，不创建第二个 recipe：

1. `nasa_crm_abupt`：NASA 单表面域，Cp 与 Cf 三分量，84 样本/epoch。
2. `nasa_crm_transolver3`：NASA 单表面域，12 维输入、4 维输出，84 样本/epoch。
3. `shapenet_car_abupt`：一个模型联合预测表面压力和体速度，789 样本/epoch。
4. `shapenet_car_transolver3_surface`：6 维输入、1 维压力输出，789 样本/epoch。
5. `shapenet_car_transolver3_volume`：3 维坐标输入、3 维速度输出，789 样本/epoch。

保持例中正式网络与采样预算。Transolver 表面为宽 256、24 层、8 头、64 切片，体积为 16 层；AB-UPT NASA 单域使用 `pssssssssss`，不能换回含跨域 c 块的汽车配置。

50 epoch 是遍历完整训练分片 50 轮，不是 50 次更新。batch=1、累积=1 时，NASA 各 4200 次更新，汽车各 39450 次更新。每轮仍使用模型规定的采样；完整遍历样本不等于每轮监督全部物理点。

保持 `batch_size=1`、`num_workers=0`、`precision=fp32`、`evaluation_enabled=false`、`ema_decay=null`。目前共享物理工作流不支持任意修改这些执行设置。五组从头训练，不续接历史单轮权重。最后一轮权重统一用于 post，不按测试结果选优。

建议用 rsync 传输并保留完整相对结构。不要向新的 `DOJO_JOB` 复制历史 `training-runs.json`、`post-runs.json`、preparation 或 checkpoint；执行工具会跳过已登记 succeeded 的案例，不会因为 YAML 改成 50 自动重训。

## 4. 迁移物理 PT 与清单

已有 PT 时优先复用，不重复 rawprep。清单 `samples[].path` 可以是相对清单位置的路径，也可能仍指向本机绝对目录；`statistics.path` 也须检查。只改 example 的 `data_root` 不会自动改这些引用。

在**服务器副本**中按原根→新根精确映射 `samples[].path` 和 `statistics.path`，必要时更新实际被读取的 topology 引用；保留 `source` 的历史来源说明，并另外保存迁移映射记录。不要递归替换所有字符串或改样本 ID、字段、分片和 PT 数值。迁移前后以文件摘要核对张量未变。清单变更会改变数据摘要，必须重新 trainprep，不沿用本机冻结准备。

若需要从原始数据重建：先完成下一节配置，再每个数据集仅运行一次 rawprep：

```bash
uv run --no-sync python "$DOJO_JOB/examples/nasa_crm_transolver3/rawprep.py"
uv run --no-sync python "$DOJO_JOB/examples/shapenet_car_abupt/rawprep.py"
```

仅在对应物理输出根尚未生成时执行。汽车已有 PT 不执行第二条。NASA HDF5→模型无关 PT，汽车按 rawprep 字段/几何/过滤声明生成 PT。任何样本失败都先解决，不把缺样本清单送入正式训练。

## 5. 复制五例并生成 50 轮配置

下面代码仅复制配置与共享入口，不启动训练。要求新实验根中没有 examples，避免覆盖已有实验。配置写成解析后的绝对路径：比较工具直接读取 YAML，不替调用方展开 `${...}`。

```bash
uv run --no-sync python - <<'PY'
import json, os, shutil
from pathlib import Path
from omegaconf import OmegaConf
repo, job = Path(os.environ['DOJO_REPO']), Path(os.environ['DOJO_JOB'])
selection = json.loads((repo / '.context/mvp/cross-model-results/selection.json').read_text())
names = ['nasa_crm_abupt', 'nasa_crm_transolver3', 'shapenet_car_abupt',
         'shapenet_car_transolver3_surface', 'shapenet_car_transolver3_volume']
assert not (job / 'examples').exists(), '换新实验根，禁止覆盖已有配置'
for name in names:
    target = job / 'examples' / name
    shutil.copytree(repo / 'examples/aero_cfd' / name, target)
    family = 'nasa' if name.startswith('nasa') else 'shapenet'
    prefix = 'NASA' if family == 'nasa' else 'CAR'
    cfg = OmegaConf.load(target / 'config.yaml')
    cfg.dataset.root = os.environ[f'DOJO_{prefix}_RAW']
    cfg.data_root = os.environ[f'DOJO_{prefix}_PT']
    cfg.run_root = str(job / 'runs' / name)
    cfg.paths.datasets.predictions = str(job / 'predictions' / name)
    cfg.train.manifest = str(Path(cfg.data_root) / 'manifest.json')
    cfg.train.max_epochs = 50
    cfg.train.device = 'cuda'
    cfg.train.precision = 'fp32'
    cfg.train.evaluation_enabled = False
    cfg.train.resume = None
    cfg.train.pop('preparation', None)
    cfg.post.samples = selection['samples'][family]
    cfg.post.checkpoint = 'last'
    cfg.post.overwrite = False
    cfg.pipeline.stages = ['trainprep', 'train', 'post']
    OmegaConf.save(OmegaConf.create(OmegaConf.to_container(cfg, resolve=True)), target / 'config.yaml')
(job / 'selection.json').write_text(json.dumps(selection, indent=2))
print(job)
PY
```

`max_epochs=50` 同时控制 Transolver 的逐轮 cosine `T_max` 和 AB-UPT 的更新总预算，无需添加另一个调度字段。学习率、优化器、网络和采样参数保留各例原声明。不要从已完成的单轮调度继续追加 49 轮。

名单来自排序后的测试样本，通过独立 NumPy default_rng(42) 无放回选五个，前三个出图。这里直接复制原冻结名单以保持比较对象一致；若换数据版本，须重新冻结并明确作为新实验，不能偷偷丢掉找不到的样本。

## 7. 正式训练、预测与比较

在 tmux 会话或服务器作业调度器中执行以下三步；环境变量需在会话/作业中保持。示例单 GPU：

```bash
export CUDA_VISIBLE_DEVICES=0
set -o pipefail
uv run --no-sync python tools/verification/cross_model/train.py "$DOJO_JOB" 2>&1 | tee "$DOJO_JOB/train-console.log"
# 仅在训练退出码为 0 且五例验收通过后执行：
uv run --no-sync python tools/verification/cross_model/post.py "$DOJO_JOB" 2>&1 | tee "$DOJO_JOB/post-console.log"
# 仅在五组 post 成功后执行：
uv run --no-sync python tools/verification/cross_model/compare.py "$DOJO_JOB" 2>&1 | tee "$DOJO_JOB/compare-console.log"
```

train 工具按 YAML 的 max_epochs 执行，不硬编码单轮；各模型在独立子进程顺序运行。每例自动执行 trainprep 和 train。post 工具消费 training-runs 中的最后检查点与 preparation，五样本全点推理后发布具名物理预测。NASA Transolver 使用全部 20 块逐层汇总与解码，不用独立逐块前向替代。

失败时保留日志、registry、当前运行及已提交预测。工具会跳过成功案例，但**不会自动恢复失败训练的轮次**。如需恢复，保持原 50 轮配置，用已有有效检查点设置 `train.resume`，另核对恢复轨迹与本次登记；不要直接重新执行并宣称无重复训练。post 失败重跑也需先核对已提交预测与 overwrite 策略，不能把旧目录存在当作成功。

仅更新报告图片：

```bash
uv run --no-sync python tools/verification/cross_model/compare.py "$DOJO_JOB" --render-only
```

这要求 comparison 数据及其 VTP 引用仍在原位置。原始几何已更换时应重新比较，不能仅重渲染。

### 8.1 数值报告

两份 HTML 标题分别为 `nasa | AB-UPT vs Transolver-3` 和 `shapenet | AB-UPT vs Transolver-3`。每个域一个总体指标表，列为 Model、Field、Elements、MSE、MAE、Relative L2。

机器可读真源为各域 `comparison.json`：`status` 标记完成状态，`models` 标记两模型，`domain` 标记域，`metrics` 保存总体指标，`completed` 保存逐样本指标，`visuals` 保存图形与切面引用。训练轮数与设备以相应运行的 training.json / training-protocol.json 为准，不能从图片推断。

NASA：Cp、Cf 三分量及模长；汽车：压力、速度三分量及模长。MSE/MAE 按真实元素累计，Relative L2 为整体误差 L2 / 真值 L2，不简单平均样本相对误差。零真值范数为 JSON null / 页面 undefined，保留绝对误差。非有限预测拒绝完成。

### 8.2 云图与曲线

每幅云图有五个并列视窗：真值、AB-UPT、Transolver-3、AB-UPT 绝对误差、Transolver-3 绝对误差。前三项共享色标、几何与视角；两个误差共享另一色标。向量云图为模长，图上的误差是模长之差的绝对值，不是向量误差范数。

- NASA 三个样本：每样本 Cp/Cf 模长两张表面图，20%/50%/80% 半展长各两张截面曲线，共 **24 PNG**。曲线同图叠加真值与两模型，横轴为物理 X，未归一成 x/c；不得冒称论文式无量纲弦向图。NASA 没有体场。
- 汽车三个样本：每样本一张压力表面图、中间 Y 与 Z 平面各一张速度模长切面，共 **9 PNG**。两模型共用切片几何与插值，无效区域排除、不填零。
- 文件名为 `<domain>-<visual序号>-<field>.png`，页面图注给出样本/字段/图种。`rendering.json` 保存图片路径及色标；`render-progress.json` 必须 succeeded。

## 9. 完成门禁与下载

核对五个 training registry 都 succeeded，并读取真实训练记录确认 epochs=50、updates=4200/39450、history 长度 50、所有损失有限；training-protocol 的实际设备是 cuda、精度 fp32，初始化和最终权重摘要不同。核对五个 post registry 的预测清单均 succeeded、样本恰为冻结五个，逐样本点 ID 唯一，真值/预测有限，指标可从物理张量复算。
