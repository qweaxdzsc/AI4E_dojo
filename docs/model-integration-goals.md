# Dojo 模型集成目标与验收原则

本文供人和 Agent 接入新模型时参考，明确目标、必要检查和交付依据，不规定固定执行流程。除明确的前置门槛外，具体方法、工具、步骤组织和实现方案由执行者结合案例判断，并遵守用户范围与仓库规则。

使用入口：[dojo-integrate-model skill](../.agents/skills/dojo-integrate-model/SKILL.md)。框架事实从[仓库索引](../.context/index.md)查阅，分层与依赖遵循[现行架构](AI4E_Dojo_ARCHITECTURE%20%281%29.md)。本文不另建一套架构规范。

## 1. 目标与交付要求

### 集成目标

1. **Dojo 能够集成目标模型。** 模型的研究流程能够在 Dojo 中运行，相关能力与框架合理协作。
2. **能够通过 recipe 复现和使用。** 人和 Agent 能理解流程、参数及输入输出，并开展实验。
3. **支持参数更新与变体开发。** 研究者能够调整设置、修改或替换相关实现，并比较基线与变体。
4. **支持模型所带的数据集。** 能够收纳和使用数据，完成原始处理与模型所需的数据准备。
5. **支持 post 与文献对标。** 能够处理模型结果，解释物理量，并按对应论文实验的指标进行比较。
6. **保留原研究结果。** 使用原文算法、参数和数据集训练，Dojo 的物理量应与已复现的原仓库接近一致，并达到对应论文的验收标准；以实际结果验证。
7. **人和 Agent 使用、开发方便。** 能找到入口、理解与修改实验、定位问题并检查结果；是否方便以实际使用效果判断。
8. **三层职责合理。** ability 负责计算能力，application 负责领域步骤与交接，recipe 表达研究流程；具体组织方式依据现行架构和案例需要决定。

**持续改进方向：**每次接入都应合理复用并积累能力，使后续相近模型减少重复开发和排错。效率提升不能以降低正确性或复现要求为代价，也不要求每个更复杂的新案例都比上一个耗时更短。

### 交付要求

- 按本次范围交付可核验的结论和成果。评估、参考复现、迁移、完整验收分别说明，不把局部完成称为全部完成。
- 完整集成应交付可用的代码与 recipe、数据处理和准备能力、训练及 post 结果，以及与参考程序和论文的对照依据。
- 说明实际设置、必要修正、结果来源、尚未完成或无法解释的问题，使另一位研究者或 Agent 能理解并继续工作。材料形式、目录和详细程度按实际需要选择，不要求统一模板或重复报告。

- 阶段交付按 skill 留下简短的[改进日志](../.context/model-integration-learning.md)，以实际错误、困难和有效流程的证据支持后续修订；引用已有记录，不重复报告。日志与正式要求分开，单次经验须保留适用边界。

## 2. 必须检查的节点

### 开始评估：阅读三个来源

首先阅读 **Dojo 框架、模型自己的原代码仓库、模型对应文献**。结合相关源码与实验设置，理解框架能力和模型需求，确认讨论的是同一案例、模型变体与评价阶段。

### 考虑集成：三项条件齐备

1. **数据集是否提供：**能够取得目标实验所需的数据，来源与实验对应。
2. **文献指标是否明确：**对标的物理量、目标结果及评价口径清楚，能够据此判断是否复现。
3. **原文源码是否提供：**存在对应目标实验的参考实现，足以核查并执行相关研究流程。

三项都具备才考虑集成；缺失或尚未确认时，可以继续资料核查和补齐，但不进入正式集成。不能仅凭一个链接、同名仓库或相似实验的指标就认定满足。

### 正式迁移：原代码先复现论文

**论文是最终标准。** 先核实文献阅读准确、实验对应正确，再对照论文的算法、参数和数据设置运行原代码，检查能否复现目标结果。原代码复现通过后，才进入 Dojo 正式迁移。

论文与代码的差异必须说明并有明确处理依据；无法判定的关键歧义保留为未决问题，不暗中选择有利解释。运行成功、短训或加载权重不能代替所要求的训练复现。

### 完成验收：结果与使用目标得到验证

Dojo 按约定的原文设置完成训练和评价，既对照已复现的原程序，也对照论文。明确“接近一致”的判定依据，考虑适用的数值误差和随机波动，不根据结果事后放宽目标。

检查 recipe 使用、参数调整、变体开发、数据处理、post 和三层职责是否达到约定目标，采用足以证明这些能力的方法。结论必须对应实际证据，未运行、失败或跳过不能计为通过。

## 3. 可选参考与经验提醒

以下是辅助判断的参考，不是每个模型都要执行的检查清单。

- **定位数值差异：**可选择数据逐值、固定输入的前向和损失、单步更新、短训练、恢复或逐步推理对照；按问题选择组合与顺序，也可采用更有效的方法。这些诊断不能替代完整训练与论文对标。
- **理解实验口径：**常见差异包括数据划分、时间窗口、归一化、单位、mask、指标归约、随机性、优化更新、选优和推理后处理；只检查与当前案例相关的内容。
- **验证使用体验：**可通过复制 recipe、调整参数、替换组件或开发一个研究变体检验易用性，具体场景和数量按模型特点决定；不规定一套统一的外部安装或变体验收流程。
- **选择实现方式：**可考虑独立模型包、贡献模块、局部适配和共享能力扩展，不在这里预设具体接口、目录或抽象。是否重构由实际问题与充分理由决定，既不预设重构，也不以保护既有设计为目标。
- **提高接入效率：**可复用仍然有效的历史证据，整理新增能力、重复工作和主要困难；不必按统一表格逐阶段统计投入。不同复杂度的案例不宜只比较总耗时。
- **保持任务范围：**模型代码集成不自动包含平台建设；各模型的临时状态、实验记录和进度放在其专项材料中，通用原则保持稳定。
