### 分阶段检查顺序

1. 数据：逐参数身份、轴序、数量、参考解和基矩阵摘要一致。
2. 模型：固定相同初始权重，比较自由系数及边界装配后的完整系数。
3. 计算：比较 u、需要的各阶导数、PDE/数据/IC/BC 分项及加权总目标。
4. 优化：比较反向梯度、一次 Adam 更新后的权重与 optimizer state；确认无未声明裁剪、归约或调度。
5. 正式预算：按参数表的实际更新数训练，记录全程历史；R 不要求数学上有问题的原 PDE 残差变成正确物理残差。
6. 独立评价：新进程重建模型及所有基/边界上下文，核对全测试名单、全部时空点和指标定义；包含预测保存的补充项必须真的落盘。
7. M 数学校验：额外以解析多项式/SciPy 导数、初边值重建和制造解验证后，再开始独立训练；M 的结果使用不同实验 ID。

建议的旁置产物包含：`run.json`（配置/来源/环境/实际模式）、`samples.json`（实例和分片）、数据文件、`basis.json` 与必要矩阵、初始与最终权重、`history`、逐实例预测与坐标、`metrics.json` 和分阶段数值对照。名称是补充交付约定，不宣称作者仓库已提供这些文件。

### 原始入口的执行方式

在独立工作目录准备已核对的副本和依赖后，Python 主脚本可使用 `uv run python convection_diffusion.py` 或 `uv run python neumann_bc.py`。这两个入口默认还有其他模型分支；按功能项 4 在副本选择 PI-BSNet，并保留数据生成与评价部分。未选择分支就运行原脚本，会训练其他模型，不是单模型预算。

Notebook 使用复现路径表中的单元顺序。若转换为脚本，先把所需 source 单元按顺序拼接，并处理安装魔法命令；不得只抽出模型类便称完整流程。AD/BU/TR 原流程需要内存对象，因此补充保存和重载步骤是跨进程交付所必需的。

改变生成数量、控制点数、网格或 epochs 可以做调试，但结果须标记缩小规模，不满足本表正式预算。原仓库随附的 `test_one_step.py` 是本地未跟踪辅助文件，不作为官方训练流程或正式复现验收证据。
