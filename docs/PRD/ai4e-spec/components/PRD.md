## 一、数据与模型组件协议

### 1.1 背景与定位

数据来源与模型结构彼此不同，公开约定覆盖数据按需读取、内容身份、模型构造、结构描述和具名预测；不预先建立统一张量容器。这些是选择对应领域业务时的局部约定，只依赖标准库。普通组件无需继承或注册，自己的签名和返回类型由连接代码适配；不承担所有模型或平台功能的统一协议。

### 1.6 功能点详解

#### 1. 最小要求声明

物理视图明确交付具名域、点场、样本条件、身份基础与拓扑引用。已有 PT 可以通过来源布局映射接入；缺少原点映射的历史产物只声明产物行身份，不假定它与原网格编号相同。

数据组件提供分片、字段、样本身份、选择读取与内容摘要；持久数据视图通过描述交付可恢复引用和分块语义，消费者无需读取内部清单或路径属性。点字段和样本工况分别表达。协议保持轻量，无 torch 或 numpy 依赖。

组件区分必需和可选输入名称；最大批次可为空，表示由组件布局校验而非固定单样本。域、字段和嵌套张量语义由贡献模型维护，不定义通用张量格式，不依赖数值库。

#### 2. 构造器注入

物理路径的模型组件另提供训练参数提取、样本准备、监督损失和完整样本预测。准备必须验证特征和标签维度，输出保留样本身份；完整预测恢复物理量和原点顺序。切换组件不要求更换领域工作流。

选择具名模型流程时，连接适配公开 construct、describe、predict；原构造器可附加 describe 回调，保留旧构造器身份与检查点兼容。描述由组件解释，框架不猜测内部布局属性。

用户可调用对象直接接入，无需继承核心基类；参数含义由具体模型负责。
