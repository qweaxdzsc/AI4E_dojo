# 计量与主控报告

## 精度与延迟

在看测试结果前冻结误差公式、样本单位、字段/空间/时间聚合和异常处理。多场量级不同时明确逐场等权或其他科学权重，不无意用量级改变主指标。主控以约定的高精度独立复算；缺样本/非有限值不能删掉后报平均。

报告每轮候选与按验证选出的最终方案。主精度比较服从已约定的延迟/输出准入，失败候选仍展示；分别报告合格率及合格精度，避免只选幸存者。各组初始点不同还应展示绝对精度与相对自身初始点改善，不把baseline差异自动归因于Dojo。

计时口径在技能正文基础上按任务固定。多次计时重复不是独立科学样本；推理插桩与正式速度测量分开。未实测原数值求解器时不报CAE加速倍数。

## 编码时间和token

保留原始区间、进程和请求证据，按区间并集汇总，重叠关系单列。阅读Skill/帮助、搜索、规划、写代码、理解错误计编码；运行数据处理计准备；训练尝试计训练；预测/复算计评价；安装修复计环境；排队与其他等待单列。后台训练存在不意味着同时发生的编码应归训练。

不能用总时间减训练时间推算编码。模型思考/工具等待等无法精确拆分时报告可观察口径和区间；训练内验证无法拆分时标混合，不伪造秒数。正式首条指令、最终冻结、最终评价三时刻分别记录，解释冻结后批次等待。

每请求保留ID与供应商原始usage、input/output/cache字段、工具调用和重试。按编码、训练观察、评价、准备、环境、混合、未知分类；去重请求，不重复累加已包含的缓存/推理token，缺失不填0。混合请求给编码token上下界，证据不足不强行排名。Agent可修改的自报账本不能作为唯一证据；主控采集原始会话与进程事件，组织成本单列。

## Dojo利用率：三种口径分别报告

### 1. 适用能力利用率与框架承接

按实际职责判定，不按API数量打分：数据读取/校验、统计/变换、流/采样、模型、更新、验证、选优、状态/恢复、推理、评价、固定后处理和运行记录等。没有实际需要的职责不算漏用；方法特有需求与共同职责分开。

`适用能力利用率 = 已实际采用且执行的适用职责数 / 已确认冻结Dojo可承担的职责数`。

直接使用与局部适配使用分别列；Dojo缺失或实测不兼容、未验证适用性单列，未知项给范围。拆分粒度在评分前明确，不为某组增加细项。怀疑“已有却未用”需主控在副本做最小适配与等价/性能验证，不能只凭名称认定可用。

逐项给出训练更新、验证、检查点、恢复和推理实际由谁承担。只包launch或把完整手写循环藏在组件里不算使用训练框架；用户objective/stream接框架更新属于正常复用。区分读文档、导入、实际执行与最终采用，未演练恢复不能记作恢复通过。

### 2. 本地源码来源复用

冻结统一有效行口径，去空行/注释/docstring，包含用户组件与连接。给定baseline、主控评测接口、配置/非Python代码另列，不能藏在分母外却称总实现量完整。记录本地文件的既有Dojo保留部分、新写/改写、其他来源复制和未知来源。

`本地来源复用率 = 本地实际使用且保留的Dojo来源有效行 / 排除共同交付后本地有效实现行`。

需有版本、复制来源及逐块diff/身份映射。原样复制example的来源复用率可以很高，但仅有其中部分代码会直接调用Dojo；两个指标不同。修改后的整文件不能都算原样复用。重复复制、死代码和为提高比例增加的无用代码不计。

### 3. import背后的展开实现量

一行import可调用大量既有实现；同时不能把整包未使用源码算作复用。

- `L`：当前候选实际相关的本地有效实现位置，排除公共交付的原样baseline/评测接口、纯import/声明、死代码与重复复制。
- `D`：实际调用的冻结Dojo函数/方法的有效实现位置，以及保留使用的Dojo复制来源。
- 以版本＋来源文件＋源码位置归一并去重，共同来源交集只算一次。

`展开实现量 = |L ∪ D|`；`展开Dojo复用率 = |D| / |L ∪ D|`。

采用实际调用函数体口径时，另外给实际执行行数；函数曾被调用不代表整个函数体都执行。不计模块导入时未使用的类定义、无关模块或第三方库内部源码。本次新增框架补丁不算实验起始版已有能力；本地命名为dojo不改变来源。

统计整个研究流程与最终推理路径两个范围；每轮候选、当轮新增及历轮使用并集分开。失败/放弃试验计入研究使用和成本，不混为最终候选复用。原始运行追踪或冻结候选在训练/验证输入上的独立重放提供执行证据；未覆盖路径、动态/编译实现和非Python实现标缺口，不能虚报零或完整覆盖。

展开代码量是给定边界的实现体积，不是“没有Dojo必须手写这么多”的证明。若需要节省代码量，比较功能和科学语义等价的独立实现，或按共同职责逐块比较；不同架构的白板总行数不能直接作为Dojo的反事实分母。通用第三方库复用两组都记录，不冒充Dojo收益。

## 必交图表与可复核数据

每幅图注明坐标轴、单位、分组、数据口径和证据版本；横轴使用实际轮次，初始方案单列，失败或缺失为缺口而非零值。误差条只能来自真实独立重复或明确的样本不确定性，不能用优化轮代替重复。静态科学图交付可独立查看的图文件及对应数据。

1. 精度折线：验证与隐藏分开，标最终选择、最后轮和门槛失效点；测试最优只作事后诊断。
2. 编码时间折线：逐轮与累计，编码口径固定，排队/训练不混入；不确定区间可见。
3. 编码token折线：逐轮与累计，混合区间和未知可见，提供原始usage对账。
4. Dojo适用能力利用率、本地来源复用率、展开复用率与实际代码量；每点提供分子/分母，源码构成和框架承接情况。
5. 配套延迟/准入、方法改动、其他成本、复制案例/变体、未用职责及自写代码块。比较白板实际代码时标功能范围差异。

机器数据至少关联group/session/round、候选摘要、最终选择、科学指标、延迟判定、时间/token与证据完整性、职责判定和代码量。附来源/执行位置、去重映射、排除项、命令和失败恢复收据；不以组内可编辑摘要替代主控证据。

报告按技能正文“产物归属与存储”附组内产物索引与环境修订，不附整套环境、数据或冻结产物副本；主控保留独立采集的计量收据、核验结果和总结。区分组内原件、主控独有评价证据与已清理的可重建中间产物，说明引用是否仍可读及复现限制。

结论分开回答：科学效果怎样、开发成本怎样、Dojo实际被用于何处、未用是未发现/误解/适配困难还是框架缺失。Skill建议与框架扩展建议分别给出，不把所有自定义都视为失败，不反向辅导尚未结束的正式会话。
