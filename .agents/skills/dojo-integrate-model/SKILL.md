# Dojo 模型集成指引

本技能提供目标、参考和错误边界；在用户授权与仓库规则内，由 Agent 自主选择实现和验证方法。完整目标见[集成原则](../../../docs/model-integration-goals.md)，框架事实从[仓库索引](../../../.context/index.md)定位。仅评估不自动授权迁移或长训练。

**后续更新原则：**正文始终围绕「目标与交付要求」「必须检查的节点」「可选参考与经验提醒」。提炼实际复跑、困难、纠错的证据或普遍适用的流程，也保留用户明确的通用偏好；说明适用边界，不从单次案例固化模型名称、案例数量、预算或指定工具，不把单次做法固化为强制步骤。优先合并删重，具体经历留在日志。

## 1. 目标与交付要求

- **研究闭环：**通过可理解、可修改的 recipe 完成数据处理、准备、训练、推理、后处理和文献对标，支持参数修改与变体开发。
- **可信结果：**保留原算法、参数和数据语义，完整复现以物理量接近参考实现且达到论文标准为目标。交付可追溯的代码、有效配置、结果和依据，分别说明参考一致性、学习效果和论文指标达成情况。
- **能力优先进入 core：**集成时尽可能拆解、抽取计算能力放入 core，而非默认放入 contrib。首次集成往往无法充分判断通用性，不以已有多个使用者或已证明通用为前提；允许先服务当前模型，再在后续使用中逐步形成通用能力。contrib 主要保留具体模型组合、数据语义及专属连接，core 不反向依赖 contrib。ability 负责计算，application 负责领域装配与交接，recipe 表达研究流程。
- **优先快速本机验证：**集成检查尽量选择本机可训练、整体耗时小于 3 小时的方案，按原版与 Dojo、各分支及必要评价/保存合并估算，不给每一阶段另算三小时。预算用于选择合适的验证规模，不是运行到点强制中断；完整论文复现单独约定范围，缩小检查仍须保留算法语义并说明与论文设置的差异。
- **可接续、可改进：**说明已完成内容、证据、未决问题和继续入口。阶段交付须向[改进日志](../../../.context/model-integration-learning.md)追加简短记录：实际现象与证据、处理结果、适用范围及单次或重复验证；区分「已证实的错误边界」「可泛化的流程候选」「待核实观察」。引用已有证据即可，无新增则如实注明。日志不自动成为规则。

## 2. 必须检查的节点

这些是结论成立所需的检查，不是固定操作脚本。

**风险优先主流程：**开始或继续集成前，先明确当前最不确定、错误后返工代价最大的关键假设，并优先设计能直接推翻它的最小真实对照；记录输入、参考、判断标准和结果。该假设通过后再扩大能力、案例或运行规模，不能用代码完成度、测试数量或下游功能绕过尚未闭合的关键假设。

1. **制定方案前：**阅读 Dojo 框架、原仓库和对应文献，核对版本与实验身份；理解完整研究流程与数据交接，不能只按网络构造器估计能力需求。
2. **考虑集成前：**目标数据可取得且可用、文献指标与评价口径明确、对应源码足以执行研究流程；三项齐备才考虑集成，缺项时继续核查和补齐。
3. **正式迁移前：**先按论文设置完成原实现训练与评价并复现目标，说明论文与代码差异及必要修正。用户明确授权缩小范围时，按该范围交付阶段结论；短训或加载权重不能称为完整论文复现。
4. **训练或扩大计算前：**每次涉及训练的集成都先预估本机整体耗时并向用户说明；优先复用有效实测，无可靠依据时先做代表性短测速，计入评价/保存与余量。预计超过上述偏好时，先提出更小的可比方案，说明能验证什么及不能验证什么；具体规模以用户约定为准。核对实际参数和计算语义，通过实际入口验证关键交接、数值对照与产物消费，内部测试不能替代闭环；验收标准预先明确。
5. **修改或出现偏差后：**定位原因，判断哪些证据仍有效、哪些需要补验；不能为通过而放宽标准、改写历史基线，也不默认全部重跑。
6. **宣称完成前：**约定训练与对标、recipe 使用及扩展、相关兼容性均有对应实际代码和配置的证据；通过、失败、跳过和未运行分别报告，不能超出验证范围宣称完成。

## 3. 可选参考与经验提醒

- 出现差异时，可沿输入、中间量、更新和输出寻找最早不一致的位置。
- 比较前留意数据处理阶段、精度与评价口径，区分原始数据、变换结果和评价输入；只检查与当前研究相关的差异来源。
- 可通过复制运行、参数修改、组件替换和新增输出消费检验易用性；按实际风险选择验证方式，不规定统一数量或流程。
- 可留意已有验证是否覆盖本次交付的实际入口到结果消费；内部能力或另一入口运行成功，未必说明用户的使用路径也已打通。
- 复用仍有效的能力、产物和记录；架构调整以实际问题、收益及迁移影响为依据。整理日志时区分必须避免的错误与可选的有效做法，仅将经核实且边界清楚的结论用于后续 skill 修订。
